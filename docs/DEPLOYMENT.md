# Calendar Play parallel deployment

Until the policy cutoff, run `npm run deploy:parallel` from a clean committed release using Node24, the authenticated Vercel CLI, and AWS profile `fishbowl-head`. The command refuses to run from an unexpected repository/account, with uncommitted backend source, or after 2026-10-22 07:00 UTC. Read the workspace deployment policy and registry before each release.

The existing Vercel projects `calendar-play` and `calendar-play-api` have the same source and provider configuration. The command verifies their OpenAI/Unsplash values match without printing them. It builds both projects locally from a private archive of the exact commit, deploys one matching AWS Next.js service with Basic preview protection and IAM-protected Lambda URLs, and then activates both Vercel builds. Production routing stays on Vercel. Git auto-deployment is disabled for `codex/calendar-play-release` only. No business jobs, webhooks, payments or new database are introduced.

AWS uses `sst.config.ts` and OpenNext. The service serves the entire existing site, including `/`, `/support`, `/privacy`, `/api/health`, `/api/parse-event` and `/api/unsplash`. Provider keys are copied into SST secrets from the existing production environment; no key value is committed or printed. The ignored `.deploy/preview-password` is operator-only. Unsplash's unused secret key is checked for configuration equivalence but is not copied to the runtime.

The command records activation at `.deploy/deployed.json`. Activation is not verification. Check both Vercel projects and the AWS preview from the recorded revision: site pages, malformed API bodies, allowed one-event parse including date/time-zone conversion, non-event rejection, Unsplash search/random and download reporting, rate limits, CORS, and anonymous AWS rejection. POST checks through CloudFront supply `x-amz-content-sha256` so the IAM signature covers the body. Direct Lambda checks use SigV4. Never expose the preview password or include customer descriptions in test requests.

The API uses no event database or application request cache. Rate limits are bounded per-instance counters keyed by an ephemeral salted address hash. This is a local throttle, not a distributed quota or authentication. App APIs remain available to native clients without a browser Origin header. Cross-origin browser requests are rejected. AWS application log retention is one week; provider and Vercel retention are separate. Application code does not log event text, raw AI responses, Unsplash keys, or photo queries.

The deployment record must include exact source revision, both Vercel deployment URLs, AWS URL, functional/security check results and actual cutover time. Previous revisions remain available for rollback by deploying an explicitly selected committed revision through the same workflow after confirming policy state. No production cutover or rollback has been established merely by adding these files. Review sustained parity and rollback before the October cutover; preserve the working production host if that review is incomplete.
